# Windows File Cleanup Guide

**Context**: Docker-Exclusive Development Environment  
**Date**: October 22, 2025  
**Status**: Optional but Recommended

---

## Background

After transitioning to Docker-exclusive development, certain Windows directories are no longer needed:

- `node_modules/` - Now exists only in Docker named volume
- `.next/` - Build cache, now in Docker named volume  
- `.eslintcache` - ESLint cache file
- `tsconfig.tsbuildinfo` - TypeScript incremental build info
- `coverage/` - Test coverage reports

These directories may still exist on your Windows filesystem from previous development sessions. They are:

- ✅ **Safe to delete** - Docker uses isolated volumes
- ✅ **Ignored by Git** - Already in `.gitignore`
- ❌ **Not used by Docker** - Docker has its own isolated copies
- ❌ **May cause confusion** - VSCode extensions try to use them

---

## What These Directories Contain

### `node_modules/` (~500MB-1GB)

**Previous Purpose**: Installed npm packages for local development

**Current State**: 
- Contains mix of Windows and Linux binaries (CORRUPTED)
- VSCode extensions try to use it but fail
- Causes "Cannot find module 'react'" errors in Problems tab

**Docker Equivalent**: 
- Docker named volume `node_modules` at `/app/node_modules`
- Contains only Linux-native binaries
- Isolated from Windows filesystem

**Safe to Delete?** ✅ YES

### `.next/` (~100MB-500MB)

**Previous Purpose**: Next.js build output and cache

**Current State**:
- Outdated build artifacts from Windows
- Not used by Docker container
- Takes significant disk space

**Docker Equivalent**:
- Docker named volume `nextjs_cache` at `/app/.next`
- Fresh builds generated inside container
- Better performance (native Linux filesystem)

**Safe to Delete?** ✅ YES

### `.eslintcache` (~1-5MB)

**Previous Purpose**: Speed up ESLint by caching results

**Current State**:
- References Windows paths
- Not used by Docker ESLint
- May cause stale lint warnings

**Docker Equivalent**:
- ESLint runs fresh each time in Docker (fast enough)
- Or creates its own cache inside container

**Safe to Delete?** ✅ YES

### `tsconfig.tsbuildinfo` (~1MB)

**Previous Purpose**: TypeScript incremental compilation cache

**Current State**:
- Contains Windows-specific paths
- Not compatible with Docker TypeScript

**Docker Equivalent**:
- Docker named volume `tsc_cache` if needed
- Or regenerated fresh each type-check

**Safe to Delete?** ✅ YES

### `coverage/` (~10-50MB)

**Previous Purpose**: Vitest/Jest test coverage reports (HTML)

**Current State**:
- Old coverage reports from Windows
- Not up-to-date with current Docker tests

**Docker Equivalent**:
- Docker named volume `coverage_output` at `/app/coverage`
- Fresh coverage generated by Docker tests
- Can be extracted: `docker cp <container>:/app/coverage ./coverage`

**Safe to Delete?** ✅ YES

## Cleanup Commands

### Safe Cleanup (Recommended)

```powershell
cd C:\taly\Analyser\payment-analyzer-next

# Remove directories (safe - won't affect Docker)
Remove-Item -Path "node_modules" -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item -Path ".next" -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item -Path "coverage" -Recurse -Force -ErrorAction SilentlyContinue

# Remove cache files
Remove-Item -Path ".eslintcache" -Force -ErrorAction SilentlyContinue
Remove-Item -Path "tsconfig.tsbuildinfo" -Force -ErrorAction SilentlyContinue

# Verify Docker still works
docker-compose -f docker-compose.dev.yml exec app pnpm lint
```

**Expected output**: ESLint runs successfully in Docker, no errors.

### Aggressive Cleanup (if needed)

```powershell
# Stop Docker containers first
docker-compose -f docker-compose.dev.yml down

# Remove ALL generated files
Remove-Item -Path "node_modules", ".next", "coverage", "dist", "build" -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item -Path ".eslintcache", "tsconfig.tsbuildinfo", ".tsbuildinfo" -Force -ErrorAction SilentlyContinue

# Restart Docker
docker-compose -f docker-compose.dev.yml up app
```

### Disk Space Recovered

Typical savings:

- `node_modules/`: ~500MB to 1GB
- `.next/`: ~100MB to 500MB
- Others: ~20MB

**Total**: ~600MB to 1.5GB

## What NOT to Delete

### Keep These Files/Directories:

✅ `src/` - Source code  
✅ `public/` - Static assets  
✅ `docs/` - Documentation  
✅ `.git/` - Git repository  
✅ `.env.local` - Environment variables  
✅ `package.json` - Dependency manifest  
✅ `pnpm-lock.yaml` - Dependency lockfile  
✅ `tsconfig.json` - TypeScript configuration  
✅ `next.config.ts` - Next.js configuration  
✅ `docker-compose.dev.yml` - Docker configuration  
✅ `Dockerfile.dev` - Docker image definition  

### Excluded by .gitignore (safe to delete):

❌ `node_modules/`  
❌ `.next/`  
❌ `coverage/`  
❌ `.eslintcache`  
❌ `tsconfig.tsbuildinfo`  
❌ `*.log`

## VSCode Behavior After Cleanup

### Before Cleanup

**Problems Tab Shows**:
```
Cannot find module 'react' or its corresponding type declarations.
Cannot find module 'next/navigation'...
[378 errors]
```

**Cause**: VSCode extensions trying to use corrupted Windows `node_modules/`

### After Cleanup + VSCode Settings Update

**Problems Tab Shows**:
```
[No errors related to missing modules]
```

**Why Fixed**:
1. No Windows `node_modules/` to confuse extensions
2. `.vscode/settings.json` disables extensions that need node_modules
3. Extensions stop trying to analyze TypeScript/ESLint

**If errors persist**:
```
Press Ctrl+Shift+P
> Developer: Reload Window
```

## Docker Volume Management

### View Docker Volumes

```powershell
docker volume ls
```

### Inspect Volume Contents

```powershell
# See what's in node_modules volume
docker run --rm -v payment-analyzer-next_node_modules:/data alpine ls -lh /data

# See package count
docker run --rm -v payment-analyzer-next_node_modules:/data alpine sh -c "find /data -maxdepth 1 -type d | wc -l"
```

### Clean Docker Volumes (DESTRUCTIVE)

```powershell
# Stop containers
docker-compose -f docker-compose.dev.yml down

# Remove volumes (CAUTION: Deletes all Docker data)
docker-compose -f docker-compose.dev.yml down -v

# Or use pnpm script
pnpm docker:clean

# Rebuild from scratch
pnpm docker:build
pnpm docker:dev
```

**When to do this:**
- Major dependency updates not reflecting
- Suspect corrupted Docker volumes
- Want completely fresh environment

**Downside**: Rebuilds everything (~2-5 min)

## FAQ

### Q: Will deleting Windows node_modules break VSCode?

**A**: No, as long as you:
1. Updated `.vscode/settings.json` to disable extensions
2. Use Docker for all linting/type-checking
3. Reload VSCode after cleanup (`Ctrl+Shift+P` > Reload Window)

### Q: Can I still use VSCode normally?

**A**: Yes! Edit files, use Git, search, etc. - all work normally.

Only linting/type-checking needs Docker:
```powershell
docker-compose exec app pnpm lint
```

### Q: What if I accidentally delete source code?

**A**: Unlikely if you follow commands above. But if you do:
```powershell
git status  # See what was deleted
git restore .  # Restore from Git
```

All source code is tracked by Git, safe.

### Q: Do I need to re-delete after pulling from Git?

**A**: Usually no. These directories are in `.gitignore`, so Git won't recreate them.

But if you ever run `pnpm install` on Windows (don't!), you'd need to delete again.

### Q: Can I keep node_modules for reference?

**A**: Sure, but it serves no purpose. Takes disk space and may confuse extensions.

If you want to browse packages, use Docker:
```powershell
docker-compose exec app sh
cd /app/node_modules
ls -la react/
exit
```
